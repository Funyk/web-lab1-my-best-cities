# Лабораторна робота №2 — «Акустична варта»

**Дисципліна:** Веб-програмування.  
**Виконав:** Костюк Артем, **КН-42**.

Односторінковий сайт навчальної компанії з акустичного моніторингу. Структура й оформлення відповідають інструкції ЛР2 та наданому зразку: світла сторінка, зелений акцент, банер із датчиком, картки показників і послуг, попередження, журнал вимірювань, форма та темний підвал.

## Файли та запуск

```text
lab-2/
├── index.html
├── css/
│   └── style.css
├── images/
│   ├── monitoring-hero.jpg
│   └── credits.txt
└── README.md
```

Відкрийте `index.html` у браузері, зберігши вказану структуру каталогів. Для GitHub Pages сторінка доступна в підкаталозі `lab-2/` спільного репозиторію. ЛР1 у корені не замінюється. Збирання та встановлення залежностей не потрібні.

## Реалізовані вимоги

- Семантичні `header`, `nav`, `main`, `section`, `article`, `aside`, `footer`.
- Вступ, п’ять карток поточного моніторингу, чотири картки напрямів роботи, окреме попередження, таблиця з чотирма записами та форма.
- Зовнішній CSS через `<link rel="stylesheet" href="css/style.css">`.
- Селектори елементів, класів, id, атрибутів, універсальний селектор і групування.
- `width`, `height`, `padding`, `border`, `margin`, `box-sizing`, кольори, фон, шрифт і вирівнювання.
- Картки мають спільний клас `.card` та `display: inline-block`. Розкладка створена без Flexbox та Grid.
- `display: block` використаний для назви бренду, показників і полів; `inline` — для одиниці вимірювання й контактної адреси.
- `.warning` має `position: relative`, а `.warning-badge` — `position: absolute` із прив’язкою до цього попередження.
- Декоративний `.sensor-mark` повертається й зміщується через `transform: rotate(-12deg) translateY(2px)`. Це декоративна CSS-фігура з `aria-hidden="true"`.
- Кнопка змінює колір на `:hover`; кнопка та картки мають `transition`.
- Є навмисний реальний конфлікт властивості `color`, пояснений нижче.

JavaScript, готові CSS-шаблони, бібліотеки, фреймворки та препроцесори не використовуються. Ця версія демонструє матеріал ЛР2; окремий адаптивний макет із медіазапитами належить до наступної роботи.

## Каскад і specificity: точний приклад

У попередженні міститься елемент:

```html
<p id="noise-warning" class="warning-message">...</p>
```

На властивість `color` цього самого елемента одночасно претендують три правила зі спільного зовнішнього CSS:

```css
p {
  color: #526171;
}

#noise-warning {
  color: #92253a;
}

.warning-message {
  color: #8b5700;
}
```

| Селектор | Specificity `(ID, клас/атрибут/псевдоклас, елемент)` | Результат для `color` |
| --- | --- | --- |
| `p` | `(0, 0, 1)` | Поступається класу та id |
| `#noise-warning` | `(1, 0, 0)` | Перемагає: колір `#92253a` |
| `.warning-message` | `(0, 1, 0)` | Поступається id, хоча записаний пізніше |

У чотирикомпонентному навчальному записі `(inline, ID, клас, елемент)` ці значення відповідно дорівнюють `(0, 0, 0, 1)`, `(0, 1, 0, 0)` і `(0, 0, 1, 0)`. Inline-стилів у проєкті немає.

Усі три декларації — звичайні авторські стилі без `!important` та без каскадних шарів. Тому порівняння вирішує специфічність. Порядок у файлі спрацював би за однакової специфічності та інших рівних умов. Це не твердження, що id завжди перемагає будь-які стилі незалежно від їхнього походження чи важливості.

Для перевірки в DevTools виберіть `p#noise-warning.warning-message`: дві слабші декларації `color` у панелі Styles мають бути перекреслені. Очікуване значення Computed → `color` — `rgb(146, 37, 58)`. Вимкнення правила id дає класовий колір `rgb(139, 87, 0)`; після вимкнення також класового кольору лишається `rgb(82, 97, 113)` з `p`.

## Box Model та позиціонування

У `.monitor-card` задані `width: 19%`, `height: 152px`, `padding: 18px` (через `.card`), `border: 1px solid`, `margin-right: 1.25%` і `box-sizing: border-box`. Ширина включає внутрішні відступи й рамки; зовнішній відступ до ширини не входить. Наприклад, у контейнері 1120 px ширина картки становить 212,8 px, а її область вмісту — 174,8 px: `212,8 − 2 × 18 − 2 × 1`.

Рядок карток має `font-size: 0`, а самі картки відновлюють розмір шрифту. Це прибирає текстові пробіли між `inline-block`-елементами. П’ять карток займають `5 × 19% + 4 × 1,25% = 100%`; у останньої немає правого відступу. Чотири картки послуг: `4 × 23,5% + 3 × 2% = 100%`.

Попередження залишається у звичайному потоці завдяки `position: relative`. Абсолютна позначка «72 дБ» позиціонується від його країв і не займає власного місця у потоці. Правий `padding` попередження залишає для неї простір.

## Демонстраційні дані та форма

Об’єкти, адреси, контакти, вимірювання й статуси — навчальні приклади, а не результати реального моніторингу. Позначка «Норма» ілюструє стан картки; проєкт не розраховує нормативів шуму. Зображення банера є згенерованою ілюстрацією; його походження описане в `images/credits.txt`.

Форма містить ім’я, email, тип об’єкта, бажаний період, опис і кнопку. Для полів є `label`, `id`, `name`; обов’язкові поля позначені й мають `required`. Браузер перевіряє заповнення, мінімальну довжину та формат email. Бажаний період — текстовий опис; перевірки календарного діапазону в цій версії немає.

Метод `GET` із `action="index.html#order"` повторно відкриває сторінку біля форми та додає дані до адресного рядка. Заявка не доставляється автору й не зберігається як замовлення. Використовуйте тільки вигадані дані, наприклад `reader@example.com`.

## Контрольні питання

1. **Для чого використовується CSS?**  
   CSS описує вигляд HTML: кольори, шрифти, розміри, відступи, рамки й розташування елементів. У цьому проєкті HTML визначає структуру сервісу, а CSS — його оформлення.

2. **Які способи підключення CSS ви знаєте?**  
   Зовнішній файл через `<link>`, внутрішня таблиця у `<style>` і inline-стиль через атрибут `style`. У роботі використано зовнішній `css/style.css`, що відокремлює оформлення від структури.

3. **Чим відрізняється селектор елемента від селектора класу?**  
   `p` вибирає всі абзаци, а `.card` — елементи з відповідним класом незалежно від їхнього тегу. Клас можна повторно застосовувати; за інших рівних умов він специфічніший за селектор елемента.

4. **Для чого використовується id?**  
   `id` ідентифікує один елемент у документі. Він потрібен, наприклад, для посилання на секцію `#monitoring`, зв’язку `label` із полем та точкового CSS-правила `#company-description`. Значення id на сторінці мають бути унікальними.

5. **Що робить універсальний селектор `*`?**  
   Вибирає всі елементи. Тут він задає `box-sizing: border-box`. Сам `*` не додає ваги специфічності.

6. **Для чого потрібен селектор атрибута?**  
   Він вибирає елементи за наявністю або значенням атрибута. `input[type="email"]` у роботі оформлює лише поле електронної пошти.

7. **Що таке каскад CSS?**  
   Це механізм вибору декларації, яка визначить значення властивості. Він враховує застосовність правила, походження та важливість стилів, каскадні шари за їх наявності, специфічність і порядок оголошення за рівних попередніх умов. У проєкті всі правила належать одному зовнішньому авторському CSS без `!important` і шарів.

8. **Що таке specificity?**  
   Це вага селектора, яку порівнюють на відповідному етапі каскаду. Кількості id, класів/атрибутів/псевдокласів та елементів порівнюються послідовно, а не як сума балів. Наприклад, `(1, 0, 0)` сильніше за `(0, 1, 0)`.

9. **Який селектор переможе: `p`, `.warning` чи `#warning`?**  
   Якщо всі вибирають той самий елемент і задають ту саму властивість, а походження, важливість та інші умови однакові, переможе `#warning`: `(1, 0, 0)` проти `(0, 1, 0)` та `(0, 0, 1)`. У проєкті аналогічний конфлікт реалізований на `#noise-warning`.

10. **Чому CSS-правило може бути перекресленим у DevTools?**  
    Декларацію часто перекреслено, коли її значення перекрила інша декларація за правилами каскаду. Також DevTools може окремо позначати недійсні або неактивні декларації. Потрібно перевірити переможне правило й остаточне значення в Computed, а не покладатися лише на порядок рядків.

11. **Чим відрізняються margin і padding?**  
    `padding` — відстань усередині рамки між вмістом та border; `margin` — зовнішній простір за рамкою. У карток padding відсуває текст від країв, а правий margin створює проміжок між картками.

12. **Що входить до Box Model?**  
    Область вмісту (content), внутрішні відступи (padding), рамка (border) та зовнішні відступи (margin). Режим `box-sizing` визначає, до якої частини моделі належать задані width і height.

13. **Чим відрізняються block, inline-block та inline?**  
    `block` створює блок у потоці й зазвичай починається з нового рядка; для нього працюють розміри та відступи. `inline-block` розміщується в рядку поруч з іншими елементами, але має власні width, height, padding і border. `inline` розподіляє вміст у текстовому рядку; width і height для звичайного рядкового елемента не задають його розміри так, як для блока.

14. **Для чого потрібен `box-sizing: border-box`?**  
    Він включає padding і border в задані width та height. Це дозволяє передбачувано розрахувати ширину карток; margin і далі залишається зовні.

15. **Чому зміна CSS-правила іноді не змінює вигляд елемента?**  
    Селектор може не вибирати елемент, декларація може програвати каскад, бути недійсною або не діяти при поточному display. Також варто перевірити збереження файлу, шлях у link і кеш браузера. У цьому проєкті зміна `color` класу `.warning-message` не змінить попередження, доки активний специфічніший `#noise-warning`.

## Перевірка перед здачею

Локально перевіряються структура HTML, унікальність id, внутрішні якорі, шляхи до CSS та зображення, зв’язки label/полів, відсутність JavaScript, Flexbox і Grid. Окремо в браузері потрібно перевірити навігацію, форму, наведення, положення позначки й фінальний колір конфліктного абзацу. Після публікації потрібно перевірити саме адресу GitHub Pages `lab-2/`, а не лише локальну копію.
