## Компіляція SCSS

Для редагування та відтворення стилів потрібні Node.js **20.19.0 або новіший** і npm. Залежність `sass` установлена з офіційного npm registry та зафіксована у `package.json` і lockfile як **1.108.1**.

У каталозі `acoustic-watch` виконайте:

```bash
npm ci
npm run build
```

Команда `build` запускає:

```bash
sass --style=expanded --no-source-map scss/main.scss css/main.css
```

Для автоматичного перекомпілювання під час редагування:

```bash
npm run watch
```

Зупинка режиму спостереження — `Ctrl+C`. Змінюйте файли у `scss/`, потім виконуйте збірку. Не редагуйте `css/main.css` як окрему альтернативу SCSS: наступна компіляція перезапише його. HTML підключає тільки `css/main.css`.

`node_modules/` внесений у `.gitignore`: він не потрібний у репозиторії або архіві для здачі й відновлюється через `npm ci`. `package-lock.json` потрібно зберігати разом із `package.json`.

## Модулі та змінні

| Файл | Призначення |
| --- | --- |
| `_variables.scss` | Кольори, spacing, радіус, шрифт, ширина контейнера, breakpoints |
| `_mixins.scss` | Повторювані шаблони для media queries, контейнера й Flexbox |
| `_settings.scss` | Публічно передає змінні та mixins через `@forward` |
| `_base.scss` | Box sizing, body, типографіка, посилання, гнучкі зображення й базові поля |
| `_layout.scss` | Контейнери, адаптивні стани header/hero/Grid/form/footer |
| `_components.scss` | Навігація, картки, кнопки, датчик, warning, таблиця й деталі форми |
| `main.scss` | Єдина точка входу; підключає модулі через `@use` |

`@use "settings" as s` робить призначення значень явним: наприклад, `s.$color-primary` і `s.$space-md`. `@forward` об’єднує спільні налаштування в одному модулі; старий `@import` не використовується. Sass підключає CSS модуля лише один раз. Nesting застосований для `&:hover`, `&::after`, модифікаторів і локальних дочірніх елементів; глибоких ланцюжків понад три рівні немає.

### Три практичні mixins

1. `respond-to($breakpoint)` створює `@media (min-width: ...)` та вміщує правила через `@content`. Використовується для планшетного й десктопного станів.
2. `container` задає ширину `calc(100% - 32px)`, `max-width: 1120px` та автоматичні бокові поля. Використовується спільним `.container` у header, hero, main і footer.
3. `flex-layout($direction, $gap, $align, $justify)` задає Flexbox, напрямок, проміжок і вирівнювання. Використовується для header, навігації, footer та внутрішнього вмісту карток.

## Адаптивність і контрольні ширини

Обрано **Mobile First**: базова версія одноколонкова; `min-width` додає можливості ширшого екрана. Це responsive layout, який поєднує перемикання станів через media queries з гнучкими розмірами контейнера, `fr`, `minmax()` і `clamp()`.

| Компонент | Mobile: менш як 768 px | Tablet: 768–1024 px | Desktop: від 1025 px |
| --- | --- | --- | --- |
| Header | Бренд над меню; посилання переносяться | Бренд і меню поруч, перенесення дозволене | Бренд і меню поруч |
| Hero | Текст → CTA → окреме зображення | Фонове зображення з текстом у світлій частині | Збережений широкий банер ЛР2 |
| Моніторинг | 1 колонка | 2 колонки | 5 колонок |
| Послуги | 1 колонка | 2 колонки | 4 колонки |
| Форма | Один стовпчик полів | Дві колонки полів, опис на всю ширину | Дві колонки полів і textarea поруч |
| Таблиця | Прокрутка тільки всередині контейнера | Вміщується або прокручується локально | Повна ширина контейнера |
| Footer | Вертикальне розташування | Дві частини поруч, меню переноситься | Дві частини поруч |

У методичці є різниця між описовою межею «Tablet 768–1024, Desktop >1024» та прикладами `min-width: 1024px`. У цій реалізації прийнята **описова межа**: `$bp-tablet: 768px` і `$bp-desktop: 1025px`. Отже, **1024 px ще має планшетні 2/2 колонки**, а 1025 px — десктопні 5/4.

`meta viewport` має значення `width=device-width, initial-scale=1.0`. Контрольні ширини вимірюються в CSS pixels; фізичні пікселі залежать від DPR і не є прямою заміною ширини CSS viewport.

### Де використані Flexbox і Grid

- **Flexbox:** `.header-content`, `.site-nav ul`, `.footer-content`, `.site-footer nav`, внутрішня структура `.monitor-card` і `.service-card`. Це одновимірне вирівнювання елементів у рядку або колонці.
- **Grid:** `.monitoring-row` і `.service-row` через спільну `.card-row`, `.form-row` та мобільна `.hero-layout`. Сітки карток мають явну кількість колонок; `repeat(5, minmax(0, 1fr))` і подібні записи дають рівні частки доступної ширини.

`minmax(0, 1fr)` дозволяє колонці стискатися без небажаної мінімальної ширини за вмістом. Картки та поля також мають `min-width: 0`. `auto-fit` не використаний у цих сітках, оскільки лабораторна вимагає точні схеми 1/2/5 і 1/2/4.

Заголовок використовує `clamp(1.9rem, 4.1vw, 2.8rem)`: плавний розмір обмежений мінімумом і максимумом. Зображення мають `max-width: 100%`; мобільний hero додатково використовує контрольовану висоту й `object-fit: cover`. У ширших станах застосовуються `background-size: cover` і `background-position: center`.

### Таблиця, warning і форма

Таблиця зберігає `<table>`, `<caption>` і заголовки `<th scope="col">`. Її `min-width: 640px` не стискає дані до нечитабельних колонок, а `.table-container` із `width: 100%` та `overflow-x: auto` утримує прокрутку всередині. Контейнер можна сфокусувати клавіатурою; він має доступну назву.

Попередження займає ширину контейнера. На mobile правий відступ залишений лише в заголовку для позначки, тому основний текст не стискається у вузьку колонку. `white-space: nowrap` не застосовується.

Форма збережена як HTML-демонстрація з `required`, мінімальними довжинами та `type="email"`. На mobile її поля займають 100% доступної ширини. `GET` повторно відкриває `index.html#order` з параметрами в адресному рядку; заявка не доставляється автору. Для тестування потрібні вигадані дані. Контроль календарного діапазону або JavaScript-обробка не додаються.

## Збережений приклад specificity

Елемент `p#noise-warning.warning-message` одночасно підпадає під три декларації `color`:

| Селектор | Вага `(ID, клас, елемент)` | Колір |
| --- | --- | --- |
| `p` | `(0, 0, 1)` | `#526171` |
| `#noise-warning` | `(1, 0, 0)` | `#92253a` — перемагає |
| `.warning-message` | `(0, 1, 0)` | `#8b5700` |

Правило класу йде пізніше, але поступається id. Усі правила мають однакове авторське походження, без `!important` та каскадних шарів. Очікуваний `Computed → color` — `rgb(146, 37, 58)`. Значення кольорів тепер зберігаються у SCSS-змінних, але результат каскаду залишився таким самим.

## Перевірка

Компіляцію виконує встановлений Dart Sass, а не вручну створена копія CSS. Команда `npm run build` створює `css/main.css` із модулів SCSS. У коментарі згенерованого CSS зазначені ім’я, група й команда збірки.

Для завершальної браузерної перевірки використовуйте щонайменше **375, 768, 1024 і 1280 px**, додатково **767 та 1025 px** на межах. Перевірте кількість колонок, навігацію, hero, поля форми, footer і відсутність горизонтального прокручування документа. Таблицю на вузькому екрані прокручуйте всередині її області. У DevTools перевірте фактичні `display`, `grid-template-columns`, розміри та колір warning. Цей README описує план перевірки й не підміняє справжні результати браузерного тестування.

Усі дані й контакти залишаються навчальними. Hero-ілюстрація успадкована з ЛР2; походження зображення наведено в `assets/images/credits.txt`.
